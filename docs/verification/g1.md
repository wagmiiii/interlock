# Verification: Gate G1 - Venue Fill Model (Task P0-06)

- **Date Verified:** 2026-11-16
- **Status:** Resolved / Accepted (ADR-004)
- **Findings:**
  - Solana perpetual venues (such as Jupiter Perps / Drift / Zeta) use a hybrid execution architecture:
    - User submits position increase/decrease requests.
    - Keepers execute fills against pool or order book or atomic immediate execution is supported depending on market depth.
  - **Interlock Guard Attachment Mode:**
    - The `assert_oracle_sane` instruction precedes the venue user-signed request instruction in the same transaction:
      `[ComputeBudget] [Pyth price_update] [assert_oracle_sane] [venue_request_or_swap]`
    - If the oracle price is aberrant, stale, or untrusted at the moment of user signing and submission, the entire transaction atomically reverts before any collateral is committed or fees incurred.
    - The guard explicitly protects user-signed actions. It does not stop external keeper liquidations.
